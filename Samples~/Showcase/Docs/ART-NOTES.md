# BRIO: FIRST HARMONIC – art notes

How to add or change a visual without breaking the look. `DESIGN.md` section 4 ("Signal at Dusk") says
what the game looks like; this file says how the code in `Scripts/Art` holds that, and the rules a
contributor follows. Everything here is in the assembly `SfxShowcase.Art`, which references only
`SfxShowcase.Core`.

## 1. The idea in one paragraph

Flat, unlit, solid shapes on a dusk sky; the world is made of waveforms. There are no textures, no
models, no fonts and no lights. Every visual is a mesh of flat-coloured triangles generated by code, and
every colour is a vertex colour taken from `Palette`. Animation is transforms only: squash, stretch,
spin, swap.

## 2. Where things are

| Folder | File | What it is |
|---|---|---|
| `Kit` | `ArtKit.cs` | The front desk (`ArtKitBase`): one method per visual, each handing over to a generator below. Owns the two materials, the shared-mesh cache and `CreatePart`. |
| `Kit` | `Palette.cs` | Every colour, by role. The only place a colour is written. |
| `Kit` | `ArtStyle.cs` | The measurements of the style: outline 0.06 m, top line 0.2 m, strata 0.6 m every 1.8 m, circle segments. |
| `Kit` | `DepthLayer.cs` | Draw order, back to front (the renderer's sorting order). |
| `Kit` | `MeshBuilder.cs` | Collects coloured triangles (triangle, quad, rect, convex polygon, line, arc) and makes a mesh. |
| `Kit` | `Shapes.cs` | Corner lists of the convex shapes everything is built from: ellipse, rect, rounded rect, diamond, teardrop; `Outset`. |
| `Kit` | `InkedShape.cs` | A shape made of convex pieces with one Ink outline round all of them. |
| `Kit` | `ArtMaterials.cs` | Creates the two `Sprites/Default` materials. |
| `Terrain` | `TerrainArt.cs`, `StrataFill.cs` | Ground, platforms, loops; the banded body. |
| `Props` | `ChimeArt`, `WooferArt`, `StaticArt`, `ClipperArt`, `ForkArt` | One generator per level piece. |
| `Props` | `ChimeSpin`, `WooferVisual`, `ClipperWalk`, `ForkVisual` | The piece's own animation component. |
| `Character` | `CharacterArt`, `CharacterVisual`, `CharacterTrail` | Brio's parts, Brio's animation from `IPlayerState`, the speed trail. |
| `Background` | `BackgroundArt`, `ParallaxBackground` | Sky, sun, three silhouettes; keeping them behind the camera. |
| `Effects` | `EffectArt`, `PopEffect`, `ScatterEffect` | The four short bursts of `EffectKind`. |
| `Hud` | `HudArt`, `HudView`, `HudLabel`, `SpeedMeter`, `StrokeFont` | HUD, title card, results panel, and the generated lettering. |

The pattern is always the same pair: a static **`…Art`** class that *builds* (meshes and GameObjects,
works in the editor and at runtime) and, only if the thing moves, a small **MonoBehaviour** that
*animates* what was built through serialized references set by a `Configure(...)` method.

## 3. The rules

### Colour

1. **No colour outside `Palette`.** No `new Color(...)`, no `Color.red`, no hex string anywhere else in
   the project. Need a tint or an alpha? Add a named role to `Palette` (like `Sun`, `HudPanel`) or use
   `Palette.WithAlpha`.
2. **One colour, one meaning.** Brio Yellow is the player, Chime Cyan is "collect", Woofer Violet is
   "bounce", Static Red is "hurts", Fork Green is "progress". Never use these five as decoration. A new
   thing that hurts is red; a new thing that bounces is violet. Neutral things use Signal Cream or
   Dormant Grey.
3. **Colour goes into vertices, never into materials.** There are exactly two materials
   (`ArtKit.OpaqueMaterial`, `ArtKit.TransparentMaterial`); do not create a third, do not set
   `material.color`, do not use a `MaterialPropertyBlock`.
4. **No gradients** – one colour per shape. The only gradient in the game is the sky; the only fade is
   the trail and the section name. `MeshBuilder.AddQuad` with four colours exists for those two only.
5. **Value order:** background in the dark third, terrain body in the dark-middle, the cream top line
   and every interactive accent in the bright third. A new background element must be darker and less
   saturated than anything in play.

### Shape

6. **Friendly is round, dangerous is angular, structures are forks, terrain is waveforms.** Pick the
   family before you draw. Build from `Shapes` (ellipse, rounded rect, diamond, teardrop for friendly;
   rect and triangles for dangerous).
7. **Anything the player can touch (other than the ground) has the Ink outline; nothing else does.**
   Build touchable things with `InkedShape`: `Add(convexPolygon, colour)` for each convex piece of the
   silhouette, `AddDetail(...)` for marks on top (eyes, a stripe). Never draw an outline by hand, and
   never change `ArtStyle.OutlineWidth` per object. Terrain, background, effects and HUD have no outline.
8. **Pieces must be convex.** A shape that is not convex (a U, a spiky burr) is several convex pieces in
   one `InkedShape`; the outlines merge by themselves because all Ink is drawn before all colour.
9. **Size floor:** nothing interactive smaller than 0.5 m; hazards at least 1 m.
10. **Ground is read by its top line.** Every walkable surface comes from `TerrainArt` and so carries the
    cream line and the level strata. Do not make walkable geometry any other way. The line follows the
    polyline you pass in: a pit wall or a terrace side only gets its line if its vertical segment is in
    the polyline.

### Depth

11. **Draw order is `DepthLayer` plus the order of triangles in a mesh. Nothing writes depth.** Inside
    one mesh, what is added later covers what was added earlier. Between objects, the renderer's sorting
    order decides: pass a `DepthLayer` (and a small `orderOffset` for parts of one object) to
    `ArtKit.CreatePart`. Do not use z to order things; callers place visuals at z = 0.
12. **Nothing passes in front of the player** except the front half of a loop and the HUD.

### Making objects

13. **Every renderer is made by `ArtKit.CreatePart`.** It assigns one of the two materials, the sorting
    order, and switches off shadows and probes. Do not `AddComponent<MeshRenderer>()` yourself.
14. **Identical objects share one mesh:** `kit.SharedMesh("Key", BuildMesh)`. Only geometry that is
    unique (terrain, panels) or changes every frame (trail, ring, HUD text) gets its own mesh.
15. **A `Create…` returns only a visual,** unparented, at the origin, with its origin where `IArtKit`
    says (the XML comment of each method). No colliders, no gameplay, no audio. The caller names,
    parents and places it, and may move, rotate, flip or hide the root freely – so animate **children**,
    never the root's own transform.
16. **Works in the editor and at runtime.** A generator may not rely on `Awake`, `Time` or play mode.
    Animation components keep what they need in `[SerializeField]` fields set by `Configure`, because
    the object is built by the scene builder, saved, and loaded again before it ever runs.
17. **Meshes that change at runtime** are created in `Awake` (or on first use), marked dynamic, redrawn
    with a reused `MeshBuilder` (`Clear`, add, `ApplyTo`) and destroyed in `OnDestroy`.

### Motion

18. **Transforms only.** Squash and stretch, spin, lean, swap one part for another. No skeletal or
    sprite-sheet animation, no particle systems.
19. **Feedback is local.** No screen shake, no full-screen flash. An effect is at most twelve pieces,
    under half a second or so, palette colours, and removes itself.
20. **Read, never write.** Art components read `IPlayerState` / `IGameSession` and move their own
    transforms. They never call `IPlayerActor`, never raise a `GameEvents` event, never play a sound.
21. **Tunable numbers are serialized fields with a tooltip;** shape dimensions live in the `…Art` class
    that draws the shape (named constants where a number is used twice). No unexplained numbers in logic.

### Text

22. **Text is `HudLabel` + `StrokeFont`:** upper case A–Z, 0–9 and `: . / -`. To add a character, add a
    line to the glyph table in `StrokeFont.cs` (points on a 4 × 6 grid; the format is described there).
    Format numbers with `CultureInfo.InvariantCulture` so a decimal comma never reaches the font.

## 4. Recipe: adding a new level piece

Say a **Damper** – a friendly pad that slows the player.

1. **Decide its family and colour** from rules 2 and 6. It is friendly and neutral: round, Dormant Grey
   or Signal Cream. If no existing role fits, the design is wrong before the code is – talk to the art
   director; do not add a colour.
2. **Add `Props/DamperArt.cs`:** a static class with named dimension constants, a `Create(ArtKit kit)`
   and a private mesh function:
   ```csharp
   public static GameObject Create(ArtKit kit)
   {
       return kit.CreatePart("Damper", kit.SharedMesh("Damper", DamperMesh), DepthLayer.Props);
   }

   static Mesh DamperMesh()
   {
       var pad = Shapes.RoundedRect(new Vector2(-0.8f, 0f), new Vector2(0.8f, 0.3f), 0.12f);
       return new InkedShape().Add(pad, Palette.DormantGrey).ToMesh("Damper");
   }
   ```
3. **If it reacts when used,** build the moving part as a child, add a component deriving from
   `PropVisual` (`Activate`, `ResetVisual`) like `WooferVisual`, and return that.
4. **Expose it:** add the method to `IArtKit` / `ArtKitBase` (the technical director owns
   `Scripts/Core`), then one forwarding line in `ArtKit.cs`. Say in the XML comment where its origin is.
5. **Check it against section 3** – especially: outline present, one colour one meaning, at least 0.5 m,
   root transform left alone.

## 5. Things worth knowing

- **Materials.** Both are `Sprites/Default` (built-in pipeline, always included): unlit, vertex-coloured,
  two-sided, no depth write. They are the same kind on purpose; the "transparent" one only keeps
  geometry with alpha below 1 apart. The scene builder stores both inside the `ArtKit` asset.
- **Saving generated meshes.** `ShowcaseBuilder` takes the meshes made while the scene is built from
  `ArtKit.CollectGeneratedMeshes()` and writes them to `Generated/ShowcaseMeshes.asset`, so the scene file
  stays small. Meshes that change at runtime (rule 17) are not in that list and are never assets.
- **Colour space.** `MeshBuilder` converts colours for a linear-space project in one place; the project
  is gamma today.
- **HUD units.** The HUD is laid out as if the view were always 18 units tall; `HudView` scales it to the
  camera's size and finds the corners from the aspect every frame.
- **Strata are in world space.** Band *k* is at y = 1.8 k … 1.8 k + 0.6 everywhere, so separate pieces of
  ground, platforms and loops line up without any coordination.
- **Parallax.** A layer with factor *f* is `f × level width` (plus a margin) wide; `ParallaxBackground`
  and `HudView` run late (`DefaultExecutionOrder(1000)`) so they follow the camera without lag.
